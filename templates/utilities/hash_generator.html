Which one should you use

A hash turns any input into a fixed-length fingerprint. Change one character of the input and the output changes completely, which is what makes hashes useful for spotting differences.

  • SHA-256 is the sensible default. Use it unless something specifically asks for another.
  • MD5 and SHA-1 are broken for security purposes. Researchers can deliberately produce two different inputs with the same hash. They are still fine for non-security jobs like spotting duplicate files, and you will still meet them because plenty of older systems publish MD5 checksums.

Do not hash passwords with these. Password storage needs a slow algorithm built for the job, such as bcrypt, scrypt or Argon2. The algorithms here are fast by design, which is exactly what you do not want when someone is trying to guess their way through a stolen database.

Hashing only goes one way. There is no button to turn a hash back into the original text.
